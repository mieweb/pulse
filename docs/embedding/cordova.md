# Add Pulse to a Cordova app

You add `@mieweb/pulse-embed` (the client your page calls) and `cordova-plugin-pulse` (the native
plugin, `Pulse`). The plugin brings PulseKit in through CocoaPods: its `PulseKit.podspec` downloads
one zip of PulseKit's frameworks from the PulseKit GitHub Release.

The whole path, from install to a first result, is in [README.md](README.md#add-pulse-step-by-step).
This page has what is specific to Cordova.

**Before you start:** cordova-ios 8 or later, an iOS deployment target of 16.4 or later, Node
20.17 or later, Xcode 26 and CocoaPods. None of the steps on this page have been run from a
published package yet; see the [support matrix](support-matrix.md).

## Install

```sh
npm install --save-exact @mieweb/pulse-embed@rc
npx cordova plugin add cordova-plugin-pulse@rc
npx cordova prepare ios
```

- Release candidates are prereleases on the npm `rc` tag. Use `@latest` instead once a final
  release exists, and keep both packages at the same exact version.
- `cordova prepare ios` runs `pod install`, which downloads `PulseKit-xcframeworks.zip` (about
  70 MB in a test packaging run) and checks it against the SHA-256 the release lists.
- Cordova copies a plugin into both `plugins/` and `platforms/`. With PulseKit's frameworks that
  can be over 1 GB per copy; keep both, because `cordova prepare` copies from `plugins/` again.

## Set up your app

1. Set the deployment target, the Swift version and the `Info.plist` keys in `config.xml`. This is
   what the reference host's [`config.xml`](../../embed/hosts/cordova-host/config.xml) has, with
   your own app's words in the purpose strings:

   ```xml
   <preference name="deployment-target" value="16.4" />
   <preference name="SwiftVersion" value="5" />
   <platform name="ios">
     <config-file target="*-Info.plist" parent="NSCameraUsageDescription">
       <string>TimeHuddle records videos for your tickets and clock sessions.</string>
     </config-file>
     <config-file target="*-Info.plist" parent="NSMicrophoneUsageDescription">
       <string>TimeHuddle records sound with your videos.</string>
     </config-file>
     <config-file target="*-Info.plist" parent="NSPhotoLibraryUsageDescription">
       <string>TimeHuddle imports videos from Photos.</string>
     </config-file>
     <config-file target="*-Info.plist" parent="NSPhotoLibraryAddUsageDescription">
       <string>TimeHuddle saves videos to Photos.</string>
     </config-file>
     <edit-config file="*-Info.plist" mode="overwrite" target="UIViewControllerBasedStatusBarAppearance">
       <true />
     </edit-config>
   </platform>
   ```

2. Call the client from your page. The plugin sets `window.PulseKit`, and the client waits for
   `deviceready` before it answers `isAvailable()` (up to 10 s), so you can call it as your page
   starts. In a Meteor app, call it from `Meteor.startup`.

```ts
import { getPulse } from '@mieweb/pulse-embed';

const pulse = getPulse();
await pulse.configure({ hostName: 'TimeHuddle' }); // uploadMode 'pulse', the default
await pulse.setAccount({ serverOrigin: 'https://timehuddle.mieweb.org', userId: currentUser.id });
```

The rest is the same for every host: [steps 4 to 8](README.md#4-configure-pulse-on-every-page-load),
then [uploads.md](uploads.md) for your host services.

## Background uploads

`cordova-plugin-pulse` doesn't forward background URLSession events to PulseKit, and a Cordova
app's `AppDelegate` is generated by `cordova platform add`. Uploads still run in the background
without it; an upload iOS finishes while your app isn't running is picked up the next time Pulse
runs. To forward the events, add the `AppDelegate` method from
[uploads.md](uploads.md#forward-background-upload-events) to the generated project. That is
UNTESTED in a Cordova app.

## Files your page can load

A result's `export.webUrl`, and a draft's `poster.webUrl` and `export.webUrl`, are already
converted for the WebView: through Meteor's `WebAppLocalServer.localFileSystemUrl` when it's there,
otherwise `WkWebView.convertFilePath`. Load them in an `<img>` or `<video>`, or `fetch()` them;
don't write to them. A result's file stays valid until you `acknowledge()` the result; a draft's
until the next `draftsChanged` naming it.

## Results while the page reloads

The plugin holds `flowResult` and `hostRequest` events while no page is subscribed and hands them
over once the reloaded page subscribes again. Reading `pendingResults()` on every page load covers
the rest.

## Android

The Android side of `cordova-plugin-pulse` is a stub. It adds no permissions and no dependencies,
`getInfo()` answers `supported: false` with `unsupportedReason: 'device'`, and every other call
rejects with `unsupported`.

## Try it in the reference host

`embed/hosts/cordova-host` in the Pulse repo is a one-page cordova-ios 8 app with the same

## Use a PulseKit you built

Set `PULSEKIT_LOCAL` to a folder of PulseKit `*.xcframework` files before `cordova prepare`. See
[dev-loop.md](dev-loop.md#cordova), and
[README.md](README.md#use-a-local-build-instead-of-npm) for installing the packages from local
copies.
