# Add Pulse to a Capacitor app

You add two npm packages: `@mieweb/pulse-embed` (the client your page calls) and
`@mieweb/capacitor-pulse` (the native plugin, `Pulse`). The plugin pulls PulseKit's frameworks from
the PulseKit GitHub Release through Swift Package Manager.

The whole path, from install to a first result, is in [README.md](README.md#add-pulse-step-by-step).
This page has what is specific to Capacitor.

**Before you start:** Capacitor 8 with its iOS project on Swift Package Manager, an iOS deployment
target of 16.4 or later, Node 22 or later, and Xcode 26. None of the steps on this page have been
run from a published package yet; see the [support matrix](support-matrix.md).

## Install

```sh
npm install --save-exact @mieweb/pulse-embed@rc @mieweb/capacitor-pulse@rc
npx cap sync ios
```

- Release candidates are prereleases on the npm `rc` tag. Use `@latest` instead once a final
  release exists; `npm view @mieweb/pulse-embed dist-tags` lists both.
- Keep both packages at the same exact version. They are released together, and each version of
  `@mieweb/capacitor-pulse` names the PulseKit release its frameworks come from.
- `npx cap sync ios` adds the plugin to `ios/App/CapApp-SPM/Package.swift` as the product
  `MiewebCapacitorPulse`. Xcode then downloads PulseKit's frameworks from the GitHub Release (about
  70 MB of zips in a test packaging run) and checks each one against the SHA-256 the release
  lists.
- **Swift Package Manager only.** The plugin ships a `Package.swift` and no podspec. A Capacitor
  iOS project on CocoaPods (an `ios/App/Podfile`, no `ios/App/CapApp-SPM`) can't use it.
- The plugin's `Package.swift` declares iOS 15, because Capacitor's own package does. Pulse itself
  needs iOS 16.4 and reports `supported: false` below it.

## Set up your app

1. Add the `Info.plist` keys from [README.md](README.md#2-add-the-infoplist-keys) to
   `ios/App/App/Info.plist`. The reference host's
   [`scripts/ios-info-plist.sh`](../../embed/hosts/cap-host/scripts/ios-info-plist.sh) adds all
   five with `PlistBuddy`; `ios/` is regenerated by `npx cap add ios`, so add them again after it.
2. For Pulse uploads, forward background URLSession events to PulseKit from
   `ios/App/App/AppDelegate.swift`. The code is in
   [uploads.md](uploads.md#forward-background-upload-events); a file-mode-only app can skip it.
3. Call the client from your page. The client uses the plugin when
   `Capacitor.isNativePlatform()` and `Capacitor.isPluginAvailable('Pulse')` are both true, so the
   same page code runs in a desktop browser, where `isAvailable()` is false.

```ts
import { getPulse } from '@mieweb/pulse-embed';

const pulse = getPulse();
await pulse.configure({ hostName: 'TimeHuddle' }); // uploadMode 'pulse', the default
await pulse.setAccount({ serverOrigin: 'https://timehuddle.mieweb.org', userId: currentUser.id });
```

The rest is the same for every host: [steps 4 to 8](README.md#4-configure-pulse-on-every-page-load),
then [uploads.md](uploads.md) for your host services.

## Files your page can load

A result's `export.webUrl`, and a draft's `poster.webUrl` and `export.webUrl`, are already
converted with `Capacitor.convertFileSrc`, with `?v=` added so a re-export at the same path isn't
served from the WebView's cache. Load them in an `<img>` or `<video>`, or `fetch()` them; don't
write to them. A result's file stays valid until you `acknowledge()` the result; a draft's until the
next `draftsChanged` naming it.

## Android

The Android side of `@mieweb/capacitor-pulse` is a stub. It adds no permissions and no
dependencies, `getInfo()` answers `supported: false` with `unsupportedReason: 'device'`, and every
other call rejects with `unsupported`. Show your Android fallback when `isAvailable()` is false.

## Try it in the reference host

`embed/hosts/cap-host` in the Pulse repo is a one-page Capacitor 8 app that sends raw requests
through the plugin and prints every reply and event. Its
[README](../../embed/hosts/cap-host/README.md) has the steps; use it to tell a plugin problem from
a problem in your page. Tap **Set account** before **Record**. Its contract page runs the host
contract suite against the real plugin on the phone.

## Use a PulseKit you built

Set `PULSEKIT_LOCAL` to a folder of PulseKit `*.xcframework` files and start Xcode with it. See
[dev-loop.md](dev-loop.md#capacitor), and
[README.md](README.md#use-a-local-build-instead-of-npm) for installing the packages from local
tarballs.
