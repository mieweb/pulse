# @mieweb/capacitor-pulse

The Capacitor 8 plugin `Pulse`: the native transport between `@mieweb/pulse-embed` and PulseKit.
It passes JSON requests and replies through unchanged and delivers PulseKit's events to your page.
It holds no Pulse logic; your page calls Pulse through `@mieweb/pulse-embed`, never this plugin
directly.

Setup steps are in the Pulse repo's [docs/embedding/](../../../docs/embedding/README.md), with
what is specific to Capacitor in [capacitor.md](../../../docs/embedding/capacitor.md). Releases are
prereleases on the npm `rc` tag; install both packages at the same exact version.

```sh
npm install --save-exact @mieweb/pulse-embed@rc @mieweb/capacitor-pulse@rc
npx cap sync ios
npx cap sync android
```

## Platforms

- **iOS:** PulseKit's xcframeworks come from the PulseKit GitHub Release as Swift Package Manager
  binary targets, each checked against its SHA-256 (`Package.swift`). Pulse runs on iPhone with
  iOS 16.4 or later. The plugin has no podspec, so the host's iOS project must use Swift Package
  Manager (Capacitor 8's `ios/App/CapApp-SPM`).
- **Android:** PulseKit's AAR, `com.mieweb.pulse:pulsekit` at the plugin's version, as a Maven
  dependency. Pulse runs on Android 7.0 (API 24) or later; see [Android](#android).

## Files

| Path                       | What it is                                                                                                                                            |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Package.swift`            | Generated by `embed/scripts/write-package-swift.mjs`. The committed copy is a `0.0.0-dev` placeholder; the release workflow writes the published one. |
| `ios/Sources/PulsePlugin/` | The plugin: `call({ json })` → `{ json }`, and an `event` listener.                                                                                   |
| `android/build.gradle`     | The `pulsekitAndroid` switch, PulseKit's dependency and `PULSEKIT_ANDROID_LOCAL`.                                                                     |
| `android/src/main/`        | What both Android plugins share: an empty manifest and `PulseUnsupported`.                                                                            |
| `android/src/pulsekit/`    | The Android plugin: the same `call` and `event` as iOS, over PulseKit.                                                                                |
| `android/src/stub/`        | The stub (`pulsekitAndroid=false`).                                                                                                                   |

`PULSEKIT_LOCAL=<folder of *.xcframework>` makes `Package.swift` use a PulseKit you built instead
of the release ([dev-loop](../../../docs/embedding/dev-loop.md#capacitor)).

The repo's `embed/hosts/cap-host` is a test app for this plugin.

## Android

1. Set `minSdkVersion = 24` (or higher) in the host's `android/variables.gradle`.
2. Until Maven Central has PulseKit, download `PulseKit-android-maven.zip` from the PulseKit GitHub
   Release, unzip it, and list the folder in the host's `android/build.gradle`. The app has to
   list it itself, because a library's repositories don't resolve the app's classpath:

   ```groovy
   allprojects {
       repositories {
           google()
           mavenCentral()
           maven { url = uri('/absolute/path/to/android-maven') }
       }
   }
   ```

3. `npx cap sync android`. PulseKit's AAR brings its own manifest: `PulseActivity`, the upload
   service, and the camera and microphone permissions.

From this repo, where the plugin's version is `0.0.0-dev`, set `PULSEKIT_ANDROID_LOCAL` to the
Maven repository `npm run build:android` wrote (`embed/artifacts/android-maven`). The plugin then
adds that repository and takes the one PulseKit version it holds. `pulsekitAndroidVersion` (a
Gradle property, or `ext` in the root `build.gradle`) names another version.

**Opting out:** `pulsekitAndroid=false` in the host's `gradle.properties` (or
`ext { pulsekitAndroid = false }`) builds the stub instead: no PulseKit dependency, no
permissions. `getInfo()` then reports `supported: false`, and every other call answers
`unsupported`.

**Results:** `open` starts Pulse's Activity through Capacitor's Activity-result bridge and resolves
once, when the flow ends. If Android destroyed the host Activity in the meantime (low memory, or
Developer options › Don't keep activities), the page reloads and the original promise is gone:
Capacitor sends the reply to `App.addListener('appRestoredResult', …)` (`@capacitor/app`), with
`pluginId: 'Pulse'`, `methodName: 'call'` and `data.json` holding the reply envelope. The result is
also in `pendingResults()`, which stays the way to read it, and the retained `flowResult` event
reaches the new page's listener.
